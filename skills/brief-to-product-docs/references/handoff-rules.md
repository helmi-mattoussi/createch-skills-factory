# Handoff Rules

A valid handoff to `sdd-spec-writer` must state:
- what is stable enough to assume
- what remains open
- what requires explicit validation
- what the next skill must not invent

When the brief implies users must still retrieve, review, or find an item after a state-changing action:
- state that discoverability intent explicitly in the handoff
- keep the exact UX pattern open if it is not yet validated
- do not leave the next skill to infer whether post-action access still exists

Minimum no-invention boundary:
- main business objective
- main problem to solve
- main actors
- first-level scope
- first-level out-of-scope when visible
- already-identified structuring questions
