# Revision Rules

This document defines how the skill must behave when updating an existing Product Framing Dossier.

Revision of a dossier is needed when:
- new information from a client session or workshop changes the framing
- a PD has been published that affects scope or actors
- open questions have been answered and must be incorporated
- the dossier must be refreshed before re-entering the Product Quality Gate

---

# Core rule

In revise mode:

1. preserve already-validated framing elements by default
2. update only what is grounded in new information
3. do not reopen arbitrations that have already been decided unless a higher-priority source requires it
4. make changes visible when they affect scope, actors, known rules, or readiness
5. never present a scope change as minor editorial cleanup

---

# What revision is allowed to do

Revision may:

- incorporate answers to previously open questions
- promote assumptions to known rules when validation has occurred
- update arbitration points when a decision has been made
- expand scope only when explicitly guided by new validated source
- narrow scope when a higher-priority source clarifies the boundary
- update the readiness assessment based on new information
- improve wording clarity without changing framing meaning

---

# What revision must not do

Revision must not:

- silently invent new scope
- remove visible open questions because they seem resolved without documented validation
- convert arbitration points into known rules without documented decision
- change actors silently
- broaden scope because it seems natural
- erase previously documented assumptions that have not been formally validated

---

# Revision workflow

## 1. Identify what changed
Before revising, identify:
- what new source or information has arrived
- what elements of the previous dossier it affects
- whether it resolves an open question or arbitration point, or changes scope

## 2. Classify the change
For each change, determine whether it is:
- wording improvement (no framing impact)
- open question resolved
- assumption promoted to known rule
- scope refined or extended
- actor updated
- readiness status changed

## 3. Apply the change with traceability
When incorporating the change:
- update the relevant section(s)
- if the change resolves an open question, remove it from Open questions and move its outcome to Known rules or Scope
- if an arbitration point is resolved, document the decision made and who decided it
- update readiness and handoff sections accordingly

## 4. Make meaningful changes visible
When revision changes scope, actors, rules, or readiness, note the change explicitly.

Recommended short note:
```
Meaningful changes in this revision:
- Q2 (restore behavior) answered: restore is out of scope per decision in stakeholder session 2026-03-14
- D1 (permission model) resolved: only finance managers can archive, per PD-007
- readiness updated: now Partial → Yes
```

---

# Preservation rule

When in doubt, preserve:
- existing validated scope
- existing known business rules
- existing arbitration decisions already made
- existing out-of-scope items

Do not remove content that was previously agreed unless a higher-priority source explicitly supersedes it.

---

# Revision anti-patterns

Do not:
- rewrite the dossier from scratch because the style is weak
- collapse open questions into invented rules for cleanliness
- remove out-of-scope items because they feel obvious
- change the business objective to match a new solution idea without arbitration
- present scope expansion as editorial improvement
